By the end of one dense day of prompting, review, and merges, Git Blocks was a match-3 RPG that teaches web development from Intern to Senior Developer.

I built it for fun. That matters. No shop brief. No agency overflow ticket. Just me, Cursor Cloud agents, and a willingness to throw away a Tetris clone when the idea got better.

Why I made it

GitHub READMEs cannot run JavaScript. I still wanted the profile to feel alive. Early Git Blocks was a tiny Tetris cabinet: commits as pieces, lines as merges, a high score in localStorage.

That version was fine until it was not. Gravity bugs, missing music unlock, clouds that never showed. Fixing it taught me something useful about AI coding: vague “make it better” prompts produce vague diffs. Specific failure reports produce patches you can merge.

Then I asked a sharper question: does this need to be Tetris at all? I wanted something original for the profile — closer to Jewel Quest than a falling-block clone — and tied to how I actually learn and ship web work.

For fun is a real product constraint. It means I can rewrite the genre mid-day. It also means I still owe myself a reviewable PR.

What shipped

Git Blocks is now an 8×8 match-3. You swap adjacent logo gems — HTML, CSS, JS, TypeScript, React, PHP, WordPress, Git, Node, npm. Clears write “lines of code.” Levels walk a 20-lesson path from HTML bones to Senior Developer. Background cloud words stay on the current lesson. Every clear pops a web-dev fact.

You also pick a pathway class: Classic, Frontend Mage, Backend Sentinel, WordPress Artisan, or Full-Stack Ranger. Each has a cartoon chibi, affinity gems, and a class power (Style Nova, Query Storm, Hook Cascade, Polyglot Pulse). Clear the senior path and you unlock endgame raids.

How long it took

Wall clock: one calendar day (22 Sep 2026), from morning polish on the old Tetris cabinet through evening pathway heroes. Merged pull requests tell the story better than a stopwatch.

My time was mostly prompting, watching demos, rejecting wrong genres, and clicking merge. Agent runtime was longer. Rough honest split: a few hours of my attention across the day, many more of Cloud Agent loops writing, testing, and recording walkthroughs.

I would not sell that as “built a game in an afternoon” on a client job. For a profile toy with tests and Pages deploy, the AI-assisted pace was real — and the review bar still applied.

How the idea evolved

Broken Tetris

Auto-start bugs, gravity clock wrong, clouds missing, music silent until unlock. Fix prompts with symptoms, not vibes.

Match-3 pivot

Ask for originality vs Tetris. Swap to Jewel Quest–style play with shiny web-dev logo gems and cascade FX.

Learning path

Each level teaches web dev from the beginning. Cloud words match the lesson. Facts on clear. Goal: Senior Developer.

Pathway RPG

Class select, mana powers, cartoon chibis, endgame raids. Fix the start menu when pointer-events block the cards.

How I prompted

I did not paste “build me a game.” I steered in short, concrete turns. The useful prompts looked like bug reports, genre decisions, and product goals.

Prompts that worked

  • Symptom-first bugs: “still broken — no auto-start, pieces don’t fall, clouds missing, music should unlock on Start.”
  • Genre pivot: “is this original besides Tetris?” then “make it gem match-3 with web-dev logo gems like Jewel Quest.”
  • Curriculum goal: “each level should teach web development from the beginning… background words related to what you are learning… popup facts… goal is to become a senior developer.”
  • UX polish: “start menu isn’t working… animated cartoon characters on pathway select… powers related to the pathway.”
  • Ship verbs: “merge and deploy” when Pages was ready — explicit, so the agent could squash-merge.

What I could have prompted better

  • Acceptance criteria. Not “advanced graphics” — “60fps canvas, no monochrome boards, clouds visible, music on first Play.”
  • Scope gates. Match-3 + facts first. Raids and chibis after the loop feels good on a phone width.
  • DOM contracts. “Class cards must receive clicks; do not rebuild them every frame.” That would have caught the start-menu bug earlier.
  • Seed the curriculum. Paste a one-page outline of 20 topics myself. Let the agent fill facts and cloud words.

Facts on every clear

Matching does not only score. It queues a pendingFact the UI consumes into a modal — lesson number, rank track, cloud chips, and the fact text.

That single product rule (“teach on clear”) came from my prompt. The payload shape and modal chrome came from the agent.

The start-menu bug (worth remembering)

.overlay { pointer-events: none; }
.overlay.is-clickable,
.overlay.is-class-select { pointer-events: auto; }

Class cards lived inside a non-interactive overlay, and the UI rebuilt those cards every animation frame. Clicks never stuck. The fix was boring CSS plus “build the menu once per session.” Most “AI broke my UI” stories are contracts like this.

How I kept it honest

  • Unit tests in Node for matches, curriculum, facts, pathway powers (tests/test_git_blocks.js).
  • Walkthrough artifacts — screenshots and short MP4s from Cloud Agent demos before merge.
  • Draft PRs, then squash-merge to main so Pages picked up docs/.
  • jsDelivr purge when matthummel.com loads game assets from @main (the WP page HTML still needs a separate refresh — noted for later).

Fun details I did not plan

  • Score is “lines of code,” not points. It reads better on a developer profile.
  • Cloud words are lesson vocabulary, so the board atmosphere changes as you rank up.
  • Chibis are pure SVG + CSS — no sprite sheets, so the agent could iterate without asset pipelines.
  • Original theme music lives as stack-sprint.ogg / .wav next to the player.

FAQ

Did AI write the whole game unsupervised?

No. Cursor Cloud agents wrote most of the code and tests. I set the genre, curriculum goal, and merge decisions. I also rejected paths that felt like another Tetris clone.

Is Git Blocks a WordPress plugin?

There is a sample plugin under samples/git-blocks/ for embedding the cabinet. The primary play URL is GitHub Pages from docs/. The matthummel.com /git-blocks/ page can load assets from jsDelivr @main.

Would I build a client game this way?

I would use the same prompt discipline and tests. I would not promise a one-day RPG pivot on a shop deadline without a scoped milestone list and a human design pass first.

Where should I start if I copy this approach?

Pick one core loop. Write failing tests for it. Prompt the agent against those tests. Add curriculum or cosmetics only after the loop feels good on a phone-width screen.
